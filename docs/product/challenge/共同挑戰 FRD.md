## 1. 目的

共同挑戰是島島阿學在 B2C 主題實踐之外，額外提供的一種**陪伴型集體實踐**：由平台管理者集中建立、多位使用者在同一段期間內以個人節奏參與、透過互相被看見（witnessing）而非排名比較（comparing）形成連結。

靈感卡則是使用者接觸共同挑戰的**低摩擦入口**，以「抽中」的偶然感取代「被推薦」的強迫感。

**此功能的核心目的：**

1. 擴大主題實踐以外的參與樣態，讓尚未準備好承諾長期實踐的使用者，有一個較輕量的入口參與集體節奏。
2. 強化「陪伴」與「見證」的品牌敘事：使用者在共同挑戰中的體驗，應是「與其他人一起走過一段時間」，而非「與其他人競賽」。

## 2. 範圍

### 2.1 包含範圍

- 共同挑戰的**建立與生命週期管理**（由島島阿學操作，不含前台的建立介面）。
- 共同挑戰的**參與流程**：加入、每日打卡、查看他人打卡（見證）、週摘要、結束。
- 共同挑戰的**信件流程**：Welcome → T-48h → Day 1 → 首次打卡 → 週摘要 → End，共六個節點。
- **練習抽卡**作為共同挑戰入口的抽籤機制、呈現方式與抽籤後的行為。

## 3. 功能需求

### 3.1 共同挑戰建立

- **FR-CC-01**　共同挑戰的實踐僅能由平台管理者建立，可直接由前台建立，只有我們才看得到共同挑戰選項，建立後不會直接出現在探索共同挑戰頁。
- **FR-CC-02**　建立後的共同挑戰實踐會出現在 admin 後台，類似現在的 lighthouse 模式。
- **FR-CC-03**　可點選複製、刪除、修改，自動帶到目前修改頁樣式。
- **FR-CC-04**　類似現在的 lighthouse 模式，可以設定主題並在底下設 cohort，指定使用模版和開始日。
- **FR-CC-05**　指定使用模版和開始日後，發佈至探索共同挑戰頁。

### 3.2 共同挑戰生命週期

- **FR-CC-02**　共同挑戰無「發起人」欄位、無「主揪」角色、無「隊長」概念。所有參與者於系統中位階平等，僅以加入時間排序，不做任何形式的「先加入者顯目呈現」。
- **FR-CC-03**　共同挑戰的期間須為**固定時段**（例：8/20–9/16，91 天內），所有參與者共用同一段起訖日，不提供「個人化開始日」機制。此設計旨在讓「一起走過同一段時間」成為結構性體驗。
- **FR-CC-04**　共同挑戰結束後，該挑戰進入「已結束」狀態，仍可被使用者查看歷史足跡，但不再接受新加入者。

### 3.3 加入與參與

- **FR-CC-05**　隱私不可另外設定。打卡紀錄為全公開，僅有挑戰參與者可留言。
- **FR-CC-06**　使用者加入共同挑戰後，自動複製該實踐給使用者。
- **FR-CC-07**　主題實踐卡片顯示「xx 座島已加入」。
- **FR-CC-08**　打卡機制沿用平台既有的打卡。
- **FR-CC-09**　共同挑戰實踐不可被複製（拿掉「我也想實踐」按鈕）。
- **FR-CC-10**　**不可編輯欄位**：名稱、期間。
- **FR-CC-11**　**卡片狀態**：
  - 現在加入：該實踐被加入共同挑戰時
  - 打卡（Disable）：加入，但日期未開始
  - 打卡（Enable）：開始日
  - 已完成：到期日

### 3.4 見證機制

- **FR-CC-13**　全公開，但只有參與者可留言。

### 3.5 信件流程

文案見 [共同挑戰 Email（Google Doc）](https://docs.google.com/document/d/1g3KCRKyD3kcZB2Rde5Qy9tFPUVV40VxVr90lJJfn30Y/edit)。

- **FR-CC-16**　共同挑戰的信件序列包含以下六個節點，每一節點皆有明確觸發條件：
  - **Welcome**：使用者加入後立即寄送。挑戰主題介紹、期間、對「陪伴不是打卡」的定調文案。
  - **T-48h**：挑戰開始前 48 小時寄送。開始日提醒與心情引導；不使用倒數計時樣式，改以敘事語氣呈現。
  - **Day 1**：挑戰開始當日 06:00 寄送。當日提示與首次打卡引導。
  - **First Check-in**：使用者首次於此挑戰打卡後（隔日 08:00）寄送。
  - **Weekly Summary**：每週固定日寄送，併入現有週報；每週摘要為首張卡片，其後為使用者個人的近期打卡回顧。此為週摘要唯一出現位置。
  - **End**：挑戰結束日隔日 06:00 寄送。整段陪伴的收束文案，附實踐總結頁連結（零打卡使用者的處理待決議）。

### 3.6 靈感卡入口

- **FR-LK-01**　同日最多可抽 3 次，再抽需排除已出現且之前已選過的卡，抽完後使用者可選定今天使用的卡片。
- **FR-LK-02**　紀錄使用者當次選擇哪個主題，下次抽卡時把已選擇的排除，避免出現重複。

### 3.7 靈感卡建立

- **FR-LK-03**　抽卡內容由島島從 admin 後台建立，可單獨建立一個抽卡（卡組），可重複使用，assign 給不同共同挑戰用；assign 後該主題實踐卡片 UI 出現抽卡 icon。
- **FR-LK-04**　需要欄位：抽卡名稱（那一組的名稱）、卡片數和內容。
- **FR-LK-05**　可以上傳 Excel 檔建立（欄位要求：卡片數和內容），也可直接從後台手動新增單一內容。
- **FR-LK-07**　卡片內容僅有文字，無圖片，最多 50 字。
- **FR-LK-08**　建立後可以修改、刪除、複製。

## 4. 測試重點

### 4.1 功能性測試

- **QA-CC-01**　驗證共同挑戰建立、加入、打卡、結束的完整流程於預期日程下皆能正確觸發。
- **QA-CC-02**　驗證六個信件節點皆能依觸發條件寄出，且不會重複寄送或漏發。
- **QA-CC-03**　驗證三層進度模型於行動與桌面版皆能正確切換，且切換時資料一致。
- **QA-CC-04**　驗證練習抽卡每日限 3 次的限制正確運作，跨時區使用者不會因時區差異獲得多抽機會。
