# 燈塔「模板庫 / 組織設定 / 封存」FRD

> 2026-09-11 從 Google Doc 同步：https://docs.google.com/document/d/1a9EvPpSBvpyhNXMURRm5gTjhHMF1EBA87A3YoK-UuRU/
> 對應 issue：daodaoedu/daodao#189；原型：`prototype/lighthouse-admin-preview` 分支的 `docs/product/admin/prototypes/lighthouse-admin-prototype/`

## 1. Purpose 目的

本文件定義燈塔管理後台中「模板庫」、「組織設定」與「封存」三個正式產品模組的功能需求，提供 AI 與工程團隊進行產品開發、資料模型設計、前後端拆分與測試規劃使用。

本文件以目前提供的 index.html 原型為主要業務規格依據；原型已呈現的行為會標示為「原型已確認」，正式產品需要補齊的實作行為會標示為「正式產品需求」。文件不指定未確認的 API endpoint、provider、資料庫 schema 或後端技術實作，但會描述工程開發所需的資料欄位、狀態、驗證規則、例外情境與產品邏輯。

## 2. Scope 範圍

本 FRD 涵蓋以下三個模組：

- 模板庫：模板列表、搜尋、建立模板、草稿、編輯、複製、資源管理、模板與場次綁定／解綁、已開始場次鎖定、模板封存與刪除確認。
- 組織設定：組織資訊維護、組織成員唯讀列表、未開放新增成員狀態、組織層級 AI API key 設定與連線測試狀態。
- 封存：封存分類切換、封存列表、恢復、刪除、空狀態、恢復提示，以及模板／場次／系列的封存資料處理。

不在本 FRD 範圍：

- 場次建立完整流程、活動主頁編輯、報名設定、成果摘要、動態統計與學員進度分析。
- 正式 API endpoint 命名、資料表命名、第三方 AI provider 選型、金流、通知信件內容與權限角色矩陣細節。
- 非原型中出現的批次匯入、審核流程、多語系管理與進階報表。

## 3. Functional Requirements 功能需求

### 3.1 模板庫

#### FR-TPL-01｜模板庫列表與搜尋

- 目標/描述：管理者需能在模板庫查看所有可用實踐模板，並透過搜尋快速找到目標模板。
- 原型已確認：頁面標題為「模板庫」，副標說明模板可重複使用於多次活動課程；列表以卡片呈現；搜尋欄 placeholder 為「搜尋模板名稱、標籤或資源…」；顯示「共 N 個模板」或「找到 N 個模板」；無結果時顯示「找不到符合的模板」。
- 觸發條件：使用者點擊側邊欄「模板庫」；使用者輸入或清除搜尋關鍵字。
- 前置條件：使用者具有進入管理後台與讀取模板庫的權限；模板資料已可讀取。
- 輸入/資料來源：模板清單、內建模板、客製模板、草稿模板、已封存或已刪除模板狀態、templateLibraryQuery。
- 處理邏輯：以模板名稱、標籤、說明、資源名稱與資源連結作為搜尋範圍；搜尋需排除已封存與已刪除模板；搜尋結果需與目前使用者權限相符。
- UI/狀態輸出：每張卡需顯示模板名稱、描述、最後更新日期、草稿標籤、編輯按鈕、更多操作選單、綁定狀態摘要；無結果時顯示空狀態與建立模板提示。
- 驗證規則：搜尋字串前後空白需忽略；空搜尋顯示全部可用模板；搜尋不得顯示無權限、封存或刪除項目。
- 例外/邊界：模板數量為 0 時仍需可建立模板；大量模板時需支援可維持效能的查詢與分頁或載入策略；搜尋無結果不得清除使用者輸入。
- 依賴：模板資料、模板權限、封存狀態、刪除狀態、搜尋索引或前端篩選策略。

#### FR-TPL-02｜建立與編輯模板

- 目標/描述：管理者需能建立新的實踐模板，或編輯既有模板，供場次綁定使用。
- 原型已確認：建立模板以 modal 呈現，包含 4 個步驟；步驟 1 填寫實踐行動；可自動產生模板名稱並可手動編輯；步驟 2 設定天數、每週頻率、每次分鐘、執行時段；步驟 3 設定標籤與資源；步驟 4 預覽模板；支援上一步、下一步、完成新增、完成更新與儲存草稿。
- 觸發條件：點擊「建立模板」；點擊模板卡片的編輯按鈕；在完成視窗點擊「再建立一個模版」。
- 前置條件：使用者具有模板建立或編輯權限；若為編輯，目標模板需存在且未被永久刪除。
- 輸入/資料來源：action、name、days、frequency、minutes、timing、timingOther、tags、resources、status、createdAt、updatedAt；編輯時需帶入原模板資料。
- 處理邏輯：若未填模板名稱，系統可由實踐行動推導名稱；保留自動命名但允許覆寫；完成新增或更新時狀態為 ready；儲存草稿時狀態為 draft；更新模板名稱時，若模板已綁定未開始場次，需同步更新場次中的模板名稱與開始日映射。
- UI/狀態輸出：modal 需顯示目前步驟、進度條、欄位錯誤、預覽卡、成功完成視窗；草稿模板在列表需顯示「草稿」標籤。
- 驗證規則：步驟 1 實踐行動必填且最多 50 字；模板名稱最多 20 字；步驟 2 持續天數必填且上限為 90 天；每週頻率必填且每週天數不得超過 7；每次分鐘上限為 240 分鐘；自訂時段最多 20 字。
- 例外/邊界：使用者關閉 modal 時需保護未儲存內容或明確定義是否捨棄；編輯已被封存或刪除的模板時需阻擋並提示；內建模板若允許編輯，需定義是覆寫為組織版本或直接修改原模板。
- 依賴：模板儲存、草稿狀態、場次綁定資料、日期與時間驗證、使用者權限。

#### FR-TPL-03｜模板資源管理

- 目標/描述：管理者需能在模板中加入、編輯、移除學習資源，讓場次活動主頁或實踐設定可引用。
- 原型已確認：可貼上 HTTPS 連結自動擷取資源名稱；可切換為手動輸入資源名稱；資源卡可編輯名稱與 URL；可刪除資源；資源新增時有「擷取中…」狀態與錯誤訊息。
- 觸發條件：在建立/編輯模板第 3 步貼上連結、按 Enter、點擊加入、切換手動模式、編輯資源、刪除資源。
- 前置條件：使用者位於模板建立或編輯流程；模板草稿存在於目前表單狀態。
- 輸入/資料來源：resourceLink、resourceManualName、resourceEditName、resourceEditUrl、resources[]；每筆資源至少需支援 name 與 url，可允許無 URL 的手動資源。
- 處理邏輯：只接受 HTTPS 連結；系統可依 URL hostname 或 path 推論資源名稱；若無法推論名稱，需請使用者手動命名；資源需依標準化 URL 去重；手動資源需依名稱去重。
- UI/狀態輸出：資源清單顯示名稱與 URL 或「手動新增」；錯誤時顯示原因；編輯模式支援儲存、取消、Enter 儲存、Escape 取消。
- 驗證規則：URL 必須為有效 HTTPS；同一模板內不得加入相同 URL；同一模板內不得有重複資源名稱；資源名稱不可空白。
- 例外/邊界：自動擷取失敗時不得丟失使用者輸入；URL 正規化需處理尾端斜線與大小寫；若支援 metadata fetch，需定義逾時、失敗、重試與安全掃描策略。
- 依賴：URL parser、資源 metadata 擷取能力、模板儲存、前端表單狀態。

#### FR-TPL-04｜模板複製、刪除與封存入口

- 目標/描述：管理者需能從模板卡片執行複製、封存與刪除，並透過確認流程避免誤操作。
- 原型已確認：卡片更多選單包含「複製」與「封存」；程式亦保留刪除確認 modal；複製後產生新模板並以「（複製）」加唯一編號避免重名；刪除需二次確認。
- 觸發條件：點擊更多操作、點擊複製、封存或刪除、確認或取消刪除。
- 前置條件：使用者具有模板管理權限；目標模板存在且目前未被永久刪除。
- 輸入/資料來源：template id、label、status、createdAt、updatedAt、isBuiltIn、isCustom、baseLabel、archivedTemplates、templateDeletedBuiltIns。
- 處理邏輯：複製需建立新模板 id，保留內容但更新 createdAt/updatedAt；封存需將模板移出模板庫並加入封存清單；刪除需從模板庫移除並不可在一般列表顯示；內建模板刪除應以組織層級隱藏處理，不應刪除全域原始模板。
- UI/狀態輸出：複製成功後新模板出現在列表上方；封存後模板從列表移除；刪除確認需顯示模板名稱與不可逆提醒；取消不改變資料。
- 驗證規則：新模板名稱不得與既有可見模板重複；封存與刪除需檢查權限；同一操作不得因重複點擊產生重複紀錄。
- 例外/邊界：已綁定場次的模板是否可刪除需正式產品確認；若可刪除，需定義已綁定場次是否保留快照或解除引用；原型未呈現封存確認，建議補確認或 undo。
- 依賴：模板唯一性、封存資料、刪除策略、權限與稽核紀錄。

#### FR-TPL-05｜模板與場次綁定／解綁

- 目標/描述：管理者需能將模板綁定到場次，並設定該模板在場次中的開始日，供後續實踐期間與結束日計算使用。
- 原型已確認：模板卡片顯示「綁定或解綁場次」；下拉選單列出場次並可勾選；已綁定場次顯示預覽列、開始日輸入與結束日；超過 2 筆時可開啟「查看全部 N 個綁定場次」modal；已開始場次顯示鎖頭並禁止解除綁定或修改開始日。
- 觸發條件：開啟綁定選單、勾選未綁定場次、取消已綁定場次、調整開始日、開啟全部綁定場次 modal。
- 前置條件：模板與場次皆存在；使用者具有模板與場次設定權限；場次資料含 start、end、status、practices、practiceStarts。
- 輸入/資料來源：template label/id、cohort id/name/status/start/end、practiceStarts[label]、todayDate、template days。
- 處理邏輯：綁定時需將模板加入場次 practices；若未指定模板開始日，預設使用場次 start；結束日需以模板開始日加上模板 days - 1 計算；解除未開始場次綁定前需顯示確認；已開始場次不得解除綁定或修改開始日。
- UI/狀態輸出：選單需顯示勾選、已開始標籤、disabled 狀態、tooltip；預覽列需顯示場次名稱、開始日、結束日；全部綁定 modal 需顯示所有綁定場次。
- 驗證規則：開始日必須為有效日期；已開始判斷需使用正式產品定義的基準日期與 timezone；解除綁定需刪除 practiceStarts 中對應模板的開始日。
- 例外/邊界：模板名稱變更時需同步更新場次 practices 與 practiceStarts key；場次被封存後是否仍出現在綁定清單需正式產品定義；跨時區或伺服器時間需統一。
- 依賴：場次資料、模板天數、日期計算、權限、封存狀態。

### 3.2 組織設定

#### FR-ORG-01｜組織資訊維護

- 目標/描述：管理者需能查看並維護組織對外資訊，作為平台內組織識別與活動呈現基礎。
- 原型已確認：組織設定頁包含「組織資訊」卡片；欄位包含組織名稱、組織簡介、外部連結；有「儲存」按鈕；預設示範資料為島島阿學、組織簡介與 https://daodao.so。
- 觸發條件：使用者進入「組織設定」；修改欄位；點擊儲存。
- 前置條件：使用者具有組織設定讀取權限；儲存需具有組織設定編輯權限。
- 輸入/資料來源：organization.name、organization.bio、organization.externalLink。
- 處理邏輯：讀取目前組織資料並在儲存時更新；成功後需維持欄位值並提供成功狀態；失敗時需保留使用者輸入並顯示錯誤。
- UI/狀態輸出：欄位需可編輯；儲存按鈕需支援可點擊、儲存中、成功、失敗狀態；外部連結需以 URL 格式儲存。
- 驗證規則：組織名稱不可空白；外部連結若填寫需為有效 URL；簡介需有正式產品字數上限。
- 例外/邊界：未授權使用者只能讀取或不可進入；同時多人編輯需定義衝突處理；儲存失敗不得清空欄位。
- 依賴：組織資料、權限、儲存服務、錯誤處理與稽核紀錄。

#### FR-ORG-02｜組織成員列表與新增成員狀態

- 目標/描述：管理者需能查看共同管理組織的成員；新增成員功能在原型中尚未開放，正式產品需明確定義狀態。
- 原型已確認：組織成員卡片顯示 disabled email input、disabled 新增按鈕與文字「即將推出新增組織成員功能」；列表顯示成員 Peggy 與角色「超級管理員」；每列有移除按鈕圖示。
- 觸發條件：進入組織設定；查看成員；嘗試互動 disabled 新增欄位或按鈕；點擊移除按鈕。
- 前置條件：使用者具有組織成員讀取權限；若支援移除，需具有成員管理權限。
- 輸入/資料來源：members[]，至少包含 member_id、display_name、email、role、status；新增欄位未啟用時不應送出資料。
- 處理邏輯：目前可先定義為成員列表唯讀；新增成員若未開放，需保持 disabled 並顯示 coming soon；移除成員若開放，需補確認與不可移除最後一位超級管理員規則。
- UI/狀態輸出：成員列表需顯示姓名與角色；未開放新增需用 disabled 樣式與說明文字；移除行為需明確顯示成功或錯誤。
- 驗證規則：email 格式驗證只在新增開放後生效；不可新增重複 email；不可移除自己或最後一位管理員需正式產品確認。
- 例外/邊界：成員為 0 的情境不得造成頁面空白；角色名稱需由正式權限系統提供；原型未定義邀請流程、邀請信、接受邀請或角色變更。
- 依賴：組織成員資料、角色權限、邀請服務、成員移除策略。

#### FR-ORG-03｜組織層級 AI API key 設定

- 目標/描述：組織需能保存自有 AI API key，供成果摘要等功能選擇使用平台 AI 或組織自己的 key。
- 原型已確認：組織設定頁含「AI API key」區塊；說明文字指出可在組織層級保存自己的 AI API key，之後在各場次成果摘要中可選擇使用平台 AI 或這組 API key；狀態顯示「尚未設定」或「已設定」；輸入框為 password；按鈕為「測試連線」；空值測試顯示「請先輸入 API key 再測試。」；有值測試顯示「連線測試成功（prototype demo）」。
- 觸發條件：輸入或清除 API key；點擊測試連線；其他模組選擇 own AI mode。
- 前置條件：使用者具有組織 AI 設定權限；需有安全保存與讀取狀態能力。
- 輸入/資料來源：aiApiKey、aiConnectionStatus、aiMode；至少需保存 key 的存在狀態，不應在前端回傳明文 key。
- 處理邏輯：加密保存 key；測試連線需使用後端安全流程；成功後顯示已設定；清除或未設定時顯示尚未設定；成果摘要若選擇 own mode 但未設定 key，需阻擋並提示。
- UI/狀態輸出：輸入框需遮蔽；測試連線需有未測試、測試中、成功、失敗狀態；狀態 badge 需反映是否已設定 key。
- 驗證規則：空 key 不可測試；key 格式不可只以前端 placeholder 判斷；需定義可接受 provider 與 key 格式後才做格式驗證。
- 例外/邊界：原型未定義 AI provider、model、token、錯誤碼、用量、費用或權限控管；需在安全設計中補齊，但不可由目前原型推定。
- 依賴：安全儲存、金鑰加密、AI provider 設定、成果摘要模組、權限與稽核。

### 3.3 封存

#### FR-ARC-01｜封存分類與列表

- 目標/描述：管理者需能集中查看已封存的模板、場次與系列，並依分類切換。
- 原型已確認：封存頁標題為「封存」；分類 tab 包含「模板」、「場次」、「系列」；列表欄位包含名稱、封存日期、動作；每列有「恢復」與「刪除」；沒有資料時顯示「這個分類目前沒有封存項目」。
- 觸發條件：點擊側邊欄「封存」；點擊分類 tab；封存資料改變。
- 前置條件：使用者具有封存列表讀取權限。
- 輸入/資料來源：archiveType、archivedTemplates、archivedPrograms、archived cohorts、static archive seed rows；每筆至少包含 name、type、archivedAt/date、source id、source type。
- 處理邏輯：依目前分類載入封存項目；模板分類顯示封存模板；場次分類顯示 status=archived 的場次；系列分類顯示已封存系列；已恢復或已刪除項目不得繼續顯示。
- UI/狀態輸出：目前分類需高亮；列表需顯示名稱、封存日期、恢復、刪除；空分類需顯示空狀態。
- 驗證規則：封存日期需使用正式資料 archived_at；若缺少日期，需定義 fallback，不應使用前端示範日期。
- 例外/邊界：大量封存資料需支援分頁、排序或查詢策略；無權限項目不得顯示；不同類型的封存資料需避免名稱衝突。
- 依賴：封存狀態、來源資料、權限、日期格式、列表查詢。

#### FR-ARC-02｜恢復封存項目

- 目標/描述：管理者需能將封存項目恢復至原本主要區域，並看到短暫成功提示。
- 原型已確認：每列有「恢復」按鈕；恢復後顯示「已恢復『名稱』，可回到主要區域查看。」；提示約 3 秒後清除；恢復模板會回到模板庫；恢復場次會將 status 從 archived 改回 archivedFromStatus 或 draft；恢復系列會解除 archivedPrograms 狀態並恢復其場次。
- 觸發條件：點擊封存列表列上的「恢復」。
- 前置條件：封存項目存在且未被刪除；使用者具有恢復該類型項目的權限。
- 輸入/資料來源：archive row、templateRecord、cohortRecord、programRecord、archivedFromStatus、archivedAt。
- 處理邏輯：恢復模板需移出 archivedTemplates 並回到模板庫；內建模板恢復需取消組織層級封存標記；客製模板恢復需回到 customPracticeLib；場次恢復需還原封存前狀態；系列恢復需恢復系列及其相關場次狀態。
- UI/狀態輸出：恢復成功後該列從封存列表移除；顯示成功提示；主要區域重新出現該項目。
- 驗證規則：恢復不得建立重複模板、場次或系列；恢復後名稱若與現有項目衝突，需定義衝突處理；恢復應保留原 id 以維持引用關係。
- 例外/邊界：封存項目依賴的父層已刪除時，需阻擋或要求先恢復父層；恢復已永久刪除項目不可行；恢復失敗不得從列表移除。
- 依賴：封存資料、原始項目資料、狀態還原、權限、成功提示 timer。

#### FR-ARC-03｜刪除封存項目

- 目標/描述：管理者需能從封存區刪除不再需要的封存項目，且必須經過確認。
- 原型已確認：每列有「刪除」按鈕；點擊後開啟確認 modal，標題為「確定要刪除封存項目？」；說明為刪除後不會再出現在清單中；可取消或確認刪除。
- 觸發條件：點擊刪除；確認刪除；取消刪除；點擊背景取消。
- 前置條件：封存項目存在且使用者具備刪除權限。
- 輸入/資料來源：archiveDeleteConfirm，包括 type、name、templateId、cohortId、programKey。
- 處理邏輯：確認刪除時，模板需從 archivedTemplates 移除；場次需從 cohorts 移除；系列需從 archivedPrograms 移除並標記 programDeleted，同時移除該系列下場次；示範靜態項目以 archiveDeleted 標記排除。
- UI/狀態輸出：刪除確認 modal 顯示目標名稱；刪除成功後 modal 關閉且列表移除該列；取消不更動資料。
- 驗證規則：刪除需二次確認；刪除操作需具備 idempotency，避免重複點擊造成錯誤；需定義是否為永久刪除、軟刪除或排除顯示。
- 例外/邊界：若項目已被其他人恢復或刪除，需顯示已不存在或狀態已變更；刪除系列時需明確處理子場次與引用資料；需補資料保留政策。
- 依賴：封存資料、刪除策略、權限、稽核紀錄、資料保留政策。

#### FR-ARC-04｜來源模組封存行為

- 目標/描述：模板、場次與系列從來源模組被封存後，需正確移入封存區並從主要區域移除。
- 原型已確認：模板卡片可封存；系列列表的更多選單可封存系列；場次狀態可為 archived；封存系列會使該系列不在主要系列列表顯示，並讓其場次在封存恢復時可還原。
- 觸發條件：在模板庫封存模板；在系列/場次管理中封存系列或場次；後續進入封存頁查看。
- 前置條件：來源項目存在；使用者具有該項目的封存權限。
- 輸入/資料來源：source_type、source_id、source_name、current_status、archived_at、archived_by、archived_from_status。
- 處理邏輯：封存需保留原資料與恢復所需狀態；主要列表需排除封存項目；封存列表需可依類型讀取；封存不得破壞既有歷史資料、學員資料或成果資料。
- UI/狀態輸出：封存後來源頁項目消失或狀態更新；封存頁對應分類出現項目；若封存系列，主要系列區需隱藏該系列。
- 驗證規則：封存操作需記錄封存時間與操作人；同一項目不可重複封存成多筆；已封存項目再次封存應被忽略或回傳狀態衝突。
- 例外/邊界：原型未呈現來源模組封存確認；建議補確認、undo 或成功提示；若項目正在被編輯，需處理儲存與封存衝突。
- 依賴：來源模組、封存資料、權限、狀態機、稽核紀錄。

## 4. Test Points 測試重點

- TP-TPL-01：進入模板庫時可看到標題、副標、建立模板按鈕、搜尋欄、模板數量與模板卡片。
- TP-TPL-02：搜尋模板名稱、標籤、資源名稱或資源連結時，列表與數量需同步更新；無結果需顯示空狀態。
- TP-TPL-03：建立模板流程需驗證四步驟導覽、必填欄位、錯誤訊息、預覽內容、完成新增與成功訊息。
- TP-TPL-04：儲存草稿需允許部分欄位未完成，但至少要有任一內容；草稿需在列表顯示草稿標籤。
- TP-TPL-05：資源新增需驗證 HTTPS、重複 URL、重複名稱、自動擷取失敗與手動輸入模式。
- TP-TPL-06：編輯模板名稱後，已綁定未開始場次的模板名稱與開始日映射需同步更新。
- TP-TPL-07：複製模板需產生唯一名稱與新 id，不得覆蓋原模板。
- TP-TPL-08：綁定場次需新增模板至場次；解除未開始場次需顯示確認；已開始場次需禁止解除與修改開始日。
- TP-TPL-09：封存模板後模板庫不再顯示，封存頁模板分類需出現該模板。
- TP-ORG-01：組織資訊欄位需可讀取、編輯、驗證與儲存；失敗時不得清空使用者輸入。
- TP-ORG-02：組織成員新增欄位若未開放需保持 disabled，並顯示即將推出訊息。
- TP-ORG-03：AI API key 空值不可測試；有值測試需顯示狀態；不得回傳明文 key。
- TP-ARC-01：封存分類切換需正確顯示模板、場次、系列資料與空狀態。
- TP-ARC-02：恢復封存模板、場次、系列後，封存列表移除該列，主要區域重新出現該項目，並顯示成功提示。
- TP-ARC-03：刪除封存項目需二次確認；取消不更動資料；確認後列表移除。
- TP-ARC-04：權限不足時不得看到或操作無權限的模板、組織設定或封存項目。
- TP-ARC-05：並發或重複點擊封存、恢復、刪除時不得產生重複紀錄或錯誤狀態。

## 5. Product Confirmation Items 產品待確認事項

- 模板封存是否需要二次確認或 undo；目前原型只有刪除封存項目有確認 modal。
- 內建模板的正式編輯策略：組織覆寫、複製成客製模板，或禁止直接編輯。
- 已綁定場次的模板刪除策略：禁止刪除、保留場次快照，或解除引用。
- 已開始場次的判斷基準日、timezone 與伺服器時間來源。
- 組織成員新增、角色變更與移除是否納入第一版正式產品。
- AI API key 支援的 provider、model、用量、費用、權限、加密與錯誤碼。
- 封存刪除屬於永久刪除、軟刪除或僅從封存列表隱藏。
