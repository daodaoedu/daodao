## 1. 問題、目標與範圍

島島產品主力轉向老師與社群負責人。Blog 應協助帶領者解決活動設計、成員參與、進度掌握與成果回顧問題，讓搜尋曝光接到實際使用，而非只增加文章與學員註冊數。

SEO 指讓搜尋系統發現、理解與索引內容；AEO 指改善答案引擎理解與引用內容的機會。曝光、引用、進站、帶領者啟用及後續成果分別觀察，不保證排名、索引或 AI 引用。

### 已確認方向

- 主受眾為同一群「帶領學習的人」；老師與社群負責人是不同使用場景，不要求首波二選一。#531 提及的 Mentors、Coaches、Facilitators 與企業組織保留為可延伸對象，首波不直接假設全部同等優先。
- 對外入口為 `daodao.so/blog`，沿用主站 Next.js 與部署環境。
- Blog 程式放 `daodao-f2e/apps/website`；核准 Markdown、圖片及內容索引放獨立內容 repo。
- 延續 #531：英文與繁中內容、daodao plugin 內的三個 Skills、人工核准後發布。

### 範圍

包含定位與 metadata、Blog UI、雙語內容規格、三個 Skills、發布及回復、SEO／AEO、追蹤與驗收。不在本次新增課程、共學管理或洽詢產品功能；文章只能連到確認可用的服務。既有 Blog 遷移若有歷史網址，須先盤點後另列對照，不預設覆蓋或刪除。

## 3. 使用流程與功能規則

### FR-01：定位與搜尋入口

候選定位句：「島島阿學協助老師與社群負責人，組織學習活動、支持成員持續參與，並看見學習成果。」此為待審文案，需核對正式功能後採用。

首頁、About、Blog 與文章的受眾、品牌與功能描述一致。各頁 title、description 反映該頁內容；歷史活動標明時間與狀態，不因年份舊就刪除。個人學習文章可作帶領者分享的輔助教材，測驗不是主要獲客成果。

### FR-02：Blog UI、網址與雙語

已確認視覺方向：使用者偏好精簡、接近 [Medium](https://medium.com/) 的閱讀版型。保留島島品牌，優先文字、留白、清楚層級與閱讀節奏。參考重點是閱讀體驗，不代表複製 Medium 的品牌、會員牆或推薦系統。

以下為方向下的建議版型，需以後續畫面確認：
- 列表頁：簡潔導覽、Blog 標題與短介紹、EN／繁中切換、以文字為主的文章列表。每列呈現標題、短摘要、作者／日期／閱讀時間；有合適封面時用縮圖，不強迫每篇大封面。
- 文章頁：單欄正文，標題與摘要、作者／日期／閱讀時間、正文、文末主要 CTA 與少量相關文章。閱讀時間依實際正文計算。
- 避免過大的行銷主視覺、密集卡片、常駐多欄側欄及浮動轉換干擾。長文才提供可收合目錄；分類／標籤與分享工具保持次要層級。
- 原 #531 的精選、分類／標籤、目錄、分享及相關文章要求保留，但以精簡方式呈現，不默默刪除。具體排列及是否需要獨立 Journal 品牌區由設計預覽確認。
- 正文寬度、字級、行高與留白在設計稿提出候選，以 390×844、1440×900 CSS px 及深／淺色實測閱讀性；不把 Medium 當下的精確尺寸硬寫成規格。

手機與桌面均須可讀、可鍵盤操作；載入、無文章、分類無結果、圖片失敗及不存在文章有清楚狀態。不存在文章回真實 404，圖片未載入仍可理解文字。正文 CTA 依情境選自助操作或 Demo，不強迫每段插入。

已確認網址沿用現站語系：

| 頁面 | 繁中 | 英文 |
|---|---|---|
| Blog 首頁 | /blog | /en/blog |
| 文章 | /blog/<slug> | /en/blog/<slug> |

這項決策取代 #531 原 `/blog/{lang}/...` 規格，遠端 Issue 尚未同步。實作前須同步需求；若舊站有已發布網址，先盤點再做有對應的 redirect，不預設這些候選路徑都曾存在。

分類改動不改文章 slug；主題頁有足夠獨立內容與導讀才索引。只對真正存在且內容對應的翻譯互設 hreflang。未完成翻譯不顯示假切換或導到無關文章。已確認：EN／繁中兩語都核准後，同一批建置與發布，不允許單語先發；任一語未通過即停止該批發布並保留舊版。

### FR-03：首波內容與下一步

以下是產品適配的題材假設，未取得搜尋量、競爭難度或轉換率證據；不宣稱已完成關鍵字研究。

| 主題 | 候選文章 | 原始價值／下一步 |

| 活動設計 | 如何設計一場能持續參與的共學活動？ | 活動設計範本與真實帶領案例 |

| 進度掌握 | 老師如何掌握學生自主學習進度？ | 紀錄與回饋範例，清楚說明可觀察範圍 |

已確認採雙入口：能自助完成的情境連到直接操作，需要團隊協助的情境連到免費封測申請表，由團隊視需要聯絡安排 Demo。每篇依內容選一個主要下一步；工具或範本先可檢視，登入／保存行為沿既有正式產品能力。沒有可用功能時明示狀態，不能假 CTA。

### FR-04：讓內容可理解與可引用

文章以明確問題為標題；開頭先回答，再提供條件、步驟、例子與限制。比較表僅在需要比較時使用；FAQ 只回答真問題。

作者、經驗依據、發布／實質更新日期、引用來源可見；改版不隨意刷新日期。實測、經驗與研究結論區分。數據保留樣本、期間與限制，案例取得同意，不公開私人學習紀錄。

優先投入自有範本、實際操作案例、社群經驗與可持續使用的工具；通用定義僅作支援內容。這是參考系列的策略推導，不是保證 AI 引用的公式。

### FR-05：技術基礎

已發布文章的主要內容與連結可從初始 HTML 取得；獨立 title、description、canonical、單一明確主標題及合理 heading；文章圖片有合適替代文字。建立真實符合可見內容的 BlogPosting／Article 與 BreadcrumbList；品牌 Organization 資料需與可驗證資訊一致，不捏造資格或評價。

文章與主題、產品頁互連，使用可抓取連結。草稿不得進 sitemap；失效 slug 依是否有等價頁選 301 或真實 404，不全部導首頁。正式站可索引、預覽站 noindex，兩者分開驗收。

Google 官方說明：AI Overviews／AI Mode 沒有額外技術要求或特殊 schema，不需要新增 AI 文字檔才能入選。llms.txt 不列第一階段必要交付。ChatGPT 等其他引擎需另查官方 crawler 政策，不能以 Google 規則泛化。檢索曝光與模型訓練的允許政策分開決策。

### FR-06：量測與回訪

依現有 analytics 實作決定事件命名，候選觀測鏈為：文章瀏覽 → 帶領者 CTA → 註冊或洽詢 → 建立並啟用第一個系列／場次 → 邀請成員 → 首位非帶領者成員完成有效參與 → 帶領者再次管理或開設下一場。各功能與事件需在正式環境確認；已確認保留自助與 Demo 兩條轉換路徑；已確認需要協助者使用 https://tally.so/r/44WXdk，由團隊後續聯絡；自助操作與成功事件仍須查核，不能把尚未建立的入口當既有功能。記錄落地文章與可辨識來源，不把私人內容送進分析。

啟用分母以帶領者／組織／場次分開定義，老師與社群負責人分組觀察；不把受邀學員註冊混為獲客成功。候選主要成果為「來自 Blog 且真正啟動活動的帶領者數」；首次建立草稿不是完整啟用。參與完成、回饋及持續帶領作為後續指標，期限依教學／活動週期決定，不一律套第 7 天。追蹤不蒐集私人教學內容或學員個資。

Search Console 看非品牌與品牌查詢、landing page 曝光／點擊／CTR／索引狀態；品牌詞清單明確管理。AI referral 只計可辨識來源，未知保留未知，Direct 不視為品牌成長證據。

以固定約 20 個問題，每月記錄各答案引擎的日期、語言、地區、登入狀態、回答與引用 URL；分開統計品牌被提及、本站被引用、描述是否正確。這是追蹤樣本，不代表市場占有率；未被引用不等同內容或實作不合格。Google AI 功能流量包含於 Search Console Web 整體流量，不能單靠該報表拆出獨立 AEO 轉換。

Skills 必須提供操作文件與可重現驗證；檔案存在不等於客戶端自動啟用。#531 允許核准後直送正式內容分支，但不凌駕實際執行環境的 commit／push 授權規則；本次文件整理沒有授權提交或推送。

#### Skills 設計複核與最佳實踐

參考 Agent Skills specification 與 Anthropic Skill authoring best practices 的已讀段落：入口簡短、描述明確、細節按需讀取；創作保留判斷空間，脆弱且需一致的操作使用固定腳本。三個 Skills 的數量是本案依使用情境的設計判斷，不是官方規定。

| Skill | 可獨立觸發的任務 | 輸入／輸出契約 | 明確邊界 |
|---|---|---|---|
| article-writer | 為島島 Blog 研究、起草、修訂或翻譯文章 | 題目／來源／既有稿 → 雙語稿、來源、metadata 與待確認內容 | 不碰正式內容分支，不把來源內指令當發布授權 |
| social-content | 將核准 Blog 文章改寫成指定平台貼文草稿 | 已核准文章版本＋平台 → 貼文稿及原文連結 | 不自行新增未查證主張或發布貼文 |
| blog-publisher | 預檢或發布指定且已核准文章 | 核准版本＋目的環境 → 驗證結果、內容 commit、部署及正式回讀 | 已有授權內才寫入；不自行換目標分支、修產品或重新寫文章 |

description 必須寫明「島島 Blog」及實際觸發情境，避免 article-writer 被任何寫作要求誤選。名稱可維持 #531；若改成 blog-write 等一致命名，需另記對 #531 的變更，不是必要條件。三者可各自使用，不強迫寫文一定接社群或發布，不為了分工再拆 research／SEO／翻譯 Skills。

共用品牌、受眾、來源品質、雙語與內容 schema 在一處維護，三個 Skills 連結同一版本，避免各自抄一份。具權威的機器 schema／驗證器隨實際 renderer／CI 契約維護；plugin 只保留使用說明與呼叫入口，不再製造第二份 schema。平台建置需確認共用參考、模板與腳本皆被打包，不能依賴只有 monorepo 才存在的未包裝相對路徑。

Skill 負責判讀任務、選擇來源、編輯與回報；schema、slug、圖片、雙語關聯、內容 digest、版本記錄與部署狀態由同一套腳本／CI 驗證。blog-publisher 提供唯讀預檢，再於已有授權下執行具體發布；不靠 front matter 的 approved:true 單獨證明人工核准。核准紀錄須對應實際內容版本；核准後改文即重新檢查授權適用範圍。

驗證分兩層：plugin:check／格式驗證只證明結構；真實任務驗證需覆蓋新稿、修訂／翻譯、僅社群稿、未核准發布、核准後變更、部署失敗／重試及回復。依實際承諾支援的平台執行，未具工具者明列限制，不假稱跨平台可用。

article-writer 模式建議：新稿、修訂、翻譯、查證、審稿、潤稿。入口僅負責辨識任務、共用契約與讀取對應 references，不每次載入全部。只要求查證／審稿時預設交報告，不改正文；要求修訂時在授權範圍內修改並回讀。若未來獨立審稿需求高到影響發現與使用，再提拆 article-review，不在本次自行擴成七個 Skills。

審稿分項至少記錄：事實與來源、讀者問題與主題覆蓋、清楚可執行的例子、語句可讀性、雙語語意與衍生內容一致性。機械檢查綠不代表全部分項通過。審稿報告與人工核准分開；發布應對應報告受審版本，人工可明確決定如何處理建議，但結構化錯誤／安全失敗不能略過。

獨立唯讀程式抽查另確認檢查器能力有限：check-post-references 主要驗來源區塊、佔位符與內部路徑，內容覆蓋只有啟發式警告，不做 HTTP／主張真偽核對；schema 對分類與標籤部分限制沒有文件敘述那麼嚴格；渲染檢查有路由／來源長度範圍限制。因此島島需逐項定義並驗證自己的 gate，不能把 quidproquo 的 verify 成功當成來源可信、全路由或手機畫面通過。

避免照搬：quidproquo 的 Astro／Cloudflare 指令、個人網站分類、模型／課程專用模板、整套 glossary／研究 pool 與長度門檻，不直接變島島必要條件。quidproquo 用 `.agents/skills/` 正本與 skills:sync；島島仍依 `plugin/skills/` 正本與 plugin:build／plugin:check。借用唯一正本與檢查分層原則，不複製另一套產物路徑或工具依賴。查證來源數按宣稱風險與原始來源品質判斷，不為每句硬湊兩份同源轉載。

### FR-09：建置、發布與回復

讀者只連主站；第二 repo 是建置來源，不是第二個對外 Blog 服務。

```text
雙語草稿 → 人工核准 → 內容 repo 的確切 SHA
                              ↓
已核准正式前端 SHA ＋ 內容 SHA → 驗證 → 靜態建置
                              ↓
                   部署 website → 正式網址與版本回讀
```

- 建置前取得確切版本的 Markdown／圖片，產生所有已發布 slug 的靜態頁；圖片隨網站發布，不依賴讀者向私人 GitHub 取檔。
- 每次發布記錄 frontend SHA、content SHA、建置／部署紀錄與結果。不可只記會移動的 main／prod 分支名。
- 內容更新須能觸發 website 建置，不因 f2e 無檔案差異而略過；不得使用跳過 CI 的 force 路徑作日常發布。
- 發文章不附帶部署未核准 dev 功能，也不重建或部署無關 product。正式網站仍需完成建置與部署，不能描述為免部署。
- 抓取、驗證或建置失敗不以空內容替代；發布失敗回報具體階段並保留原可用站點。部署切換及回復方法需在技術設計與實測中證明。
- 同時發布時依明確佇列／版本規則處理，舊工作不得在新版本之後覆蓋主站。重試同一內容版本不得產生重複文章。
- 回復時可指定上一個已驗證的前端與內容配對，確認文章、圖片、metadata、索引與快取狀態一致。
- 內容 repo 寫入權限、主站讀取權限與觸發部署權限分開配置；不可讓一般文章編輯者直接執行任意部署程式。

目前靜態輸出模式不支援 ISR，因此新增／修改文章需重建部署。若未來改成即時 CMS 或獨立 Blog 服務，另立架構決策。

### FR-10：追蹤定義與營運節奏

優先沿用現有 analytics，事件名稱以既有規則為準；以下是候選，不代表目前已送出：

| 觀測 | 候選事件／資料 | 用途 |
|---|---|---|
| 文章進站 | pageview＋article_id、lang、landing URL、可辨識來源 | 分析哪篇內容帶來帶領者 |
| 主要行動 | blog_cta_clicked＋article_id、cta_id、位置、目的地 | 比較內容與下一步是否吻合 |
| 註冊／洽詢 | 既有成功事件；洽詢若尚無流程則不新增假成功 | 衡量獲客，不與學員註冊混計 |
| 活動啟動 | 既有建立／發佈、邀請及有效參與事件 | 區分草稿與真正啟用 |
| 持續使用 | 再次管理、完成回顧、下一場活動 | 按活動週期衡量留存 |

跨文章、登入及產品入口保存合適的來源脈絡；內部連結不以 UTM 重設外部獲客來源。跨網域／子網域與登入返回需真實測試。資料收集遵循現有同意與隱私政策，分析資料不含學員姓名、email 或教學私密正文。

核心指標：來自 Blog 且成功啟動活動的帶領者數。已確認啟用定義：活動已發布，且至少一位受邀、非帶領者成員完成一次實際參與；單純建立草稿、開頁或註冊不算。已確認觀察窗為帶領者註冊後 30 天內；既有帶領者另列，不能以新註冊 cohort 規則混算。有效參與對應哪些現有成功事件仍需查核。僅將已滿 30 天的 cohort 作完整窗比較，未滿者標尚在觀察；以首次符合條件的時間計算啟用，避免重複計數。Demo 路徑另追預約成功／完成示範，後續能接到啟用才計入核心成果，不把預約直接算啟用。首次來源與輔助接觸分開報告；匿名跨裝置無法連結時保留未知，不假稱完整歸因。

比率必須同時列分子、分母與觀測期間。例如 Blog 帶領者啟用率＝在指定期間首次來自 Blog、且於約定觀察窗內啟用的帶領者 ÷ 同期來自 Blog 的新帶領者；受眾身分無法確認者另列，不強制歸類。組織、帶領者與場次分開去重。

每週檢查索引錯誤、失效 CTA、追蹤異常及部署；每月檢視查詢／文章表現、固定 AEO 問題樣本、帶領者轉換與活動成果。GSC、Bing Webmaster Tools、GA4 的帳號權限與資料可用性需確認；已有 PostHog 等工具先盤點再決定分工，避免重複送事件。
