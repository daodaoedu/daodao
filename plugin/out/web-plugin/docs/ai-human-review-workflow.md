# AI 檢核與人工審核共用流程

適用 Claude 與 Codex 的需求、開卡、開發、驗收及交付 skills。各步驟先完成可做的查核與安全、已授權的修正，交付可審閱成果；人確認原意、產品取捨與需要授權的動作，不另分配 PM／設計師／RD 固定檢查責任。

## 每次交接

AI 讀取來源與當下程式，完成適用檢核、自審修訂，附成果位置、主要依據、已修正事項、未驗證限制及需決策事項。事實問題先查明；無法查明時記錄限制和下一步，不把推測寫成事實。人回覆後重查受影響內容；已確認事項與授權不重問。

需求、技術設計與驗收分工：PRD（或既有 FRD）保存需求決策，開發文件引用同版 FR／TP／AC 及必要架構約束，報告記錄受驗版本、環境、命令和結果。任務勾選、diff audit、測試通過、部署與實際可用分別陳述；不能互相代替。

## 四平台執行對應

`plugin/skills/` 是完整規則來源，其餘平台的檔案都是 `pnpm plugin:build` 的產物。路徑以 skill 文件位置解析，repo／任務路徑用實際 checkout 定位。工具名稱只表示能力：

| Skill 中的能力 | 執行方式 |
|---|---|
| Read／Grep／Bash | 使用當前可用檔案、搜尋與 shell 工具；沒有使用者的 checkout 時改為請人貼上內容，查不到標「未查證」 |
| AskUserQuestion | 使用當前可用提問工具或簡短文字；只問缺少的決策與必要授權 |
| Task／Agent／spawn | 使用當前可用獨立 agent；不可用則標未完成獨立審查，不假稱自審等價 |
| 瀏覽器／Drive | 讀取對應 skill，確認 connector／工具可用；不可用標限制 |
| 自動閘門 | 只在確認已安裝且會觸發的客戶端視為自動 gate；其他客戶端主動執行等價檢查，無法等價者明列缺口 |

各平台的實際差異：

| | Claude Code | Codex／ChatGPT 桌面 | ChatGPT 網頁／行動 | Claude.ai |
|---|---|---|---|---|
| skill 來源 | `plugin/`（plugin 載入） | `.agents/skills/` | plugin 內的 `skills/` | 手動上傳的 zip |
| 使用者 repo | ✅ | ✅ | ❌ | ❌ |
| 閘門 | `plugin/hooks/hooks.json` 自動觸發 | `.codex/hooks.json`，**須先 `/hooks` 信任** | 無，靠 skill 內文逐項執行 | 無 |
| 收錄 skill | 13 | 13 | 13（含條件式落差說明） | 7（其餘需要 checkout） |

沒有使用者 repo 的平台上，「跑測試」「已合併」「已部署」一律不得由 agent 宣稱，必須由使用者提供證據。

入口檔案存在及格式檢查不證明客戶端實際載入或自動化已執行。Claude hooks 與 Codex hooks 是兩套設定，任一邊沒生效就等同沒有閘門。

## 授權與完成

沿用本次對話既有授權。AI 自審不新增 commit、push、PR、Issue 留言、Ready、merge、部署或刪除資源的授權。只有草稿授權就完成本機成果；需批准時先做好具體預覽，遵循 AGENTS 的 commit／push 流程。部分發布成功保存 URL 並只補未完成步驟；timeout 先回讀，不盲目重送。

「已合併」不等於部署或整體需求完成。收尾先驗證 PR 狀態及所需驗收，處理已授權的文件更新；仍有其他 repo／驗收未完成時保留未完成狀態。工作目錄清理先查 dirty、未推送 commit、未追蹤成果與使用中的 worktree。
