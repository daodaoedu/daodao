# 讀取權限驗證

任務改到 ACL、隱私、資料範圍篩選，或由這些規則造成的列表／詳情差異時使用。純 CSS、文件與不涉及讀取行為的變更可寫具體不適用理由；不要把一般樣式工作升級成跨服務測試。

## 從入口建立測試範圍

先追使用者實際入口到下游的呼叫鏈，再決定 repo 與測試。列出各服務的 ACL／SQL／ORM、cache 與資料來源；列表、搜尋、詳情、打卡／留言未必共用後端。用同一組固定資料驗證可見性一致，不能拿不同場次的成功畫面拼成一條通過的旅程。

固定資料至少能識別：資料擁有者、同範圍成員、範圍外使用者、退出／移除後使用者與範圍 ID。記錄 seed/schema 版本、帳號內部 ID、membership 狀態與私人資料標記，不貼 token、密碼或無關個資。沿用可重設的驗收 fixtures；需要新建帳號／清理時仍依 [browser-verify.md](browser-verify.md) 的 QA 信箱與資料清理規則，不能停用共用 fixture 帳號。

可見性預期沿用已確認的產品契約。公開內容可能允許未登入讀取；列表拒絕存取也可能用 200 空集合。判定需同時看 HTTP 與原始回應包含／排除的資料，不把「所有無權限都必須 403」寫成新產品規則。

## 必要證據與限制

- **真實資料庫**：改查詢或 DB ACL 時，使用與目標環境相容的 DB 引擎與 schema，在隔離測試資料上執行實際查詢／service。先證明舊版對同一案例失敗，再證明修復版通過；記執行命令、版本與輸出。mock、SQL 字串比對、schema signal 不能代替這項證據。純 client 導頁修正且查詢不變時，可附理由不適用。
- **快取撤權**：查詢有 cache 且權限可變時，先以有權限角色取得結果並確認 cache hit，再退出／移除後重發同一請求，確認私人資料不會從舊 cache 回傳。cache key 的存在不等於測到命中；無快取則附理由不適用。
- **期限邊界**：有內容保留／延遲公開期限時，固定時計驗期限當日與隔日，列表與下游結果一致，並寫清楚時區。沒有期限就附理由不適用。
- **私密內容**：檢查序列化前後的原始 HTTP body，對私訊、私人欄位與預覽等受保護標記做 negative assertions；只測畫面隱藏、Zod strip 後的物件或狀態碼不夠。

缺少真實 DB／CI／登入環境就明列未驗、影響與可執行的下一步；不把測試數量、報告格式或 gate 通過當成行為已證實。現有全棧旅程 runner 工作（#324）與本證據格式是不同交付，不宣稱寫了這份表就已完成跨 repo CI。

## task.md 與 PR body 格式

每個任務在 task.md 的 `## 驗證` 填宣告；PR body 把同版內容放在 `## 驗證證據` 內。兩者擇一：

```text
讀取權限驗證：適用
讀取權限驗證：不適用：只調整卡片間距，未改路由、資料查詢或可見性
```

適用時附以下段落，並在[核心旅程矩陣](journey-matrix.md)列正常與拒絕／撤權路徑，不能同時寫核心旅程不適用。以下是待填模板，不是已執行證據：

```markdown
### 讀取權限驗證
- 入口與服務：<入口 → 下游頁面/API，各 repo/service/ref 與權限來源>
- 固定資料：<fixture/schema/seed 版本、帳號與範圍 ID、membership、私人資料標記>
- 資料庫驗證：<✅ PostgreSQL；指令：實際命令；結果：實際觀測；證據：路徑/URL，或 不適用：具體原因>
- 快取撤權：<✅ 先讀命中 → 撤權 → 重讀的具體結果；證據：路徑/URL，或 不適用：具體原因>
- 期限邊界：<✅ 時區、期限當日/隔日的具體結果；證據：路徑/URL，或 不適用：具體原因>

| 角色 | 預期 | 實際 | 資料斷言 | 結果 | 證據 |
|---|---|---|---|---|---|
| 本人 | <狀態碼與可見資料> | <實測 HTTP> | <包含／排除的標記> | ⬜ | <證據> |
| 同範圍成員 | <狀態碼與可見資料> | <實測 HTTP> | <包含／排除的標記> | ⬜ | <證據> |
| 範圍外使用者 | <狀態碼與可見資料> | <實測 HTTP> | <排除的標記> | ⬜ | <證據> |
| 已退出或移除 | <撤權後狀態碼與資料> | <實測 HTTP> | <排除的標記> | ⬜ | <證據> |
| 未登入 | <狀態碼與可見資料> | <實測 HTTP> | <包含／排除的標記> | ⬜ | <證據> |
```

每個適用角色填實際 HTTP、資料斷言、證據與 `結果` 欄 ✅；未驗／失敗填 ⬜／❌，不可交付為通過。某角色在此產品不存在時，`實際` 欄寫 `不適用：具體原因`、`結果` 欄寫 `不適用`，其餘可填 `—`；不要打勾冒充測過。資料庫、快取與期限欄同樣只在確實不涉及時填不適用；「這次沒測」不是不適用。

本機 `pre-pr-gate.sh` 與 CI `check-pr-evidence.sh` 使用同一份 `check-read-access-evidence.py` 核對結構與聲明。它無法判定附上的帳號真是同場成員、DB 真執行過或證據連結真支持結論；AI 自審與人審仍須核對同版 diff、命令輸出與角色身份。CI 是否阻擋仍依既有 warn／block 設定，文件更新不代表已同步各 repo 或啟用 required check。
