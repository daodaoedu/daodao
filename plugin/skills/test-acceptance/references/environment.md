| 角色 | 用在 | PM 怎麼登入 |
|---|---|---|
| 未登入 | 公開頁、登入前流程 | 用沒有登入的瀏覽器視窗（無痕視窗或登出後確認） |
| 一般使用者 | 產品 Web 的使用者畫面 | `tlshare123@gmail.com`，Google 登入 |
| admin | 管理後台；需要管理員權限的產品畫面 | `peichun1213@gmail.com`，Google 登入（後台要求帳號有 admin／superadmin 角色） |
| 團主／講師、團友 | 燈塔場次、共同挑戰 | 請驗收留言必須寫明用哪個 PM 帳號、該帳號已被加進哪個組織／場次；沒寫就 BLOCKED |

驗收 fixture 帳號（主鍵 900001–900003，#323）**只能用工程的 dev-login 登入，PM 用不了**。請驗收留言指定 fixture 身分時，該步驟 BLOCKED，請工程改用 PM 帳號或把 PM 帳號加進 fixture 組織／場次（`daodao-storage` 的 `scripts/acceptance_fixtures/README.md`）。這是過去最常見的受阻原因（#277、#279、#281、#354）。

驗收使用相符的 PM 測試帳號與 Google 一般登入流程，不用工程 dev-login 代替。需要密碼、驗證碼或 Google 再次驗證時，暫停該角色的步驟，由 PM 在自己的驗收工作階段完成；不要求工程使用者代登入 PM 專用帳號，不在對話裡索取憑證或繞過登入。

## 瀏覽器

每個瀏覽器的登入狀態各自獨立，切換瀏覽器或帳號後都要重新確認登入的是誰（畫面右上角的使用者名稱或設定頁的信箱）。

**使用順序**：使用 Codex 內建瀏覽器執行產品操作與截圖。只有需要登入第二個測試帳號時，才可使用 Microsoft Edge 完成第二帳號登入；其他情況不得控制使用者的電腦。

本 skill 沒有其他客戶端的自動化瀏覽器或草稿模式。缺少內建瀏覽器、無法保留正確帳號，或無法直接貼上必要截圖時，回報受影響項目的 BLOCKED 與已觀察結果；不改用 Playwright、Chrome 控制或本機報告來替代正式驗收。

同時要用兩個角色時，先確認所需角色各自能在允許的工作階段登入；Edge 例外僅限第二帳號登入，不擴大為第二套產品操作、截圖或發布路徑。驗完產品 Web 再開後台時，留意兩邊的登入 cookie 會互相影響，切換前先確認身分。

判 BLOCKED 之前，先確認是不是工具其實做得到（#163 曾誤判）：

- **toast 一閃就消失**：toast 只會顯示約 4 秒。點完按鈕馬上截圖；來不及就讀頁面上 `[data-sonner-toast]` 的文字。
- **要測手機尺寸**：用內建瀏覽器支援的尺寸調整，確認實際 viewport 符合留言指定寬高；不需要真的手機。無法設定或確認尺寸時，只將受影響項目標 BLOCKED。
- **按了會跳出瀏覽器原生的確認框**（「確定要刪除嗎？」這種）：依原步驟選確定或取消，操作前確認內建瀏覽器能處理該分支；工具無法操作時保留受阻，不換成自動化瀏覽器代跑。

被瀏覽器擋（`ERR_BLOCKED_BY_CLIENT`）時，在允許的內建瀏覽器確認網址及受影響步驟；仍無法操作就 BLOCKED，不為排除阻擋控制使用者電腦或切換其他自動化瀏覽器。

照交接指定的完整網址與語系執行，確認實際網址、畫面及帳號符合規格。工具意外導向其他語系時，先在允許的瀏覽器操作中恢復指定入口；無法恢復就標受影響項目 BLOCKED，不以其他語系結果替代。

## 截圖與留言

- 用 Codex 內建瀏覽器擷取本次實測所需的畫面，直接複製／貼到 GitHub issue 的驗收報告留言；截圖不另存本機，也不另存 repo。
- 不建立留言草稿。驗收完成後直接發布一則含測試結果與所需截圖的 issue 留言；貼不上必要截圖時，回報 BLOCKED 原因，不發缺圖報告。
- 只有需要登入第二個測試帳號時才可操作 Edge；其餘網站測試、擷取畫面及留言流程使用 Codex 內建瀏覽器。

## App

**2026-10-29 起 App 暫不驗收**（使用者決定）：目前沒有可安裝的測試版（#333、#335、#358、#359 都曾因此受阻），請驗收留言裡的 App 步驟一律列為「本次未驗收範圍」，不判 BLOCKED，也不影響整體結果。判定方式見 SKILL.md §4。

- 不改用網頁版代替 App 步驟：網頁版不是同一個介面，網頁步驟只照留言裡本來就寫的網頁步驟測。
- 之後恢復驗收 App 時，留言必須給安裝方式（TestFlight 連結、內部分發連結或 Expo 入口），沒給或裝不起來就判 BLOCKED。
