# 從核准文章衍生社群草稿

先讀 [共用編輯契約](../../docs/blog-editorial-contract.md)。確認使用者指定平台與稿件語言；未指定時先從已有品牌頻道判斷，最多問一個會改變格式的選擇，不自動替所有平台生成。

1. 取得確切文章版本及其私人核准證據，使用 [blog-publisher](../blog-publisher/SKILL.md) publish-mode 預檢確認 digest。沒有原稿、核准紀錄或驗證工具時，交付缺項清單，不把未核准文章包裝成可直接貼出的正式文案。可提供不含內容主張的格式建議。
2. 只使用通過預檢版本的主張。平台可改開場、長度、段落與行動語句，不放大成效、不新增用戶故事；推論明標，數字與限制保留。
3. 附原文正確語系連結：繁中 `/blog/<slug>`、英文 `/en/blog/<slug>`；來源文章尚未正式可讀時註明「待發布連結」，不要謊稱已上線。
4. 針對要求平台產草稿。例如 LinkedIn 交代帶領者問題與操作啟發；Threads 可拆短串，但每段不割裂限制。避免把同一整篇直接貼給每個平台。
5. 輸出平台、語言、文章 id/content SHA/digest、文章連結、草稿及主張核對結果。來源改動使 digest 失效時停止並重新取核准版本。

沒有發布／排程動作。即使帳號 connector 可用，也不因產稿授權而呼叫送出工具。需要發文時由使用者明確另行要求並重新核對版本與有效授權。
