# 驗收報告範本

只填這次實際觀察到的內容。`<...>` 全部換掉；沒有內容的段落寫「無」，不刪標題。

標題依結果：

- PASS：`## 依照本次「請驗收」說明完成驗收`
- FAIL：`## 依照本次「請驗收」說明完成驗收，發現問題`
- BLOCKED 或未測完：`## 本次驗收未完成：發現問題或測試受阻`，並明列沒執行的項目

```markdown
<!-- daodao:acceptance-report spec=<規格留言 ID> result=<PASS|FAIL|BLOCKED> -->
# 驗收說明

## <依結果選上面的標題>

<SKILL.md §8 表格對應的開頭那句，含 @vincentxuu>

- Issue：<連結>
- 專案／項目：<project 與 item 連結或 ID>
- 執行前 Status：Acceptance（<確認時間，台北時間>）
- 驗收依據：<規格留言連結、作者、ID、建立／更新時間；舊格式留言註明「依舊格式留言」>
- 測試環境／帳號角色：<網址、組織或社群、角色；不寫帳密>
- 執行時間：<日期時間，台北時間>
- 整體結果：PASS／FAIL／BLOCKED
- 完成範圍：<通過／失敗／受阻的必測項數；沒有執行任何測試要明說>
- 狀態處理：<PASS：報告確認後關閉 issue，卡片將移到 Done／FAIL：報告確認後將卡片移到 Need Fix／BLOCKED：報告確認後卡片留在 Acceptance 並加上 acceptance:blocked>

## 驗收步驟

| 步驟／對照 AC | 操作與輸入 | 預期結果 | 實際結果／證據 | 結果 |
|---|---|---|---|---|
| <原步驟編號／AC-0x> | <實際做的操作，或「未執行」> | <規格寫的預期> | <觀察到的結果或受阻原因；FAIL 寫「兩次重現」；引用截圖編號> | PASS／FAIL／BLOCKED |

## 失敗與阻擋

<每個 FAIL：步驟／AC、重現步驟與輸入、預期 vs 實際、畫面上的錯誤文字、兩次重現的證據。
每個 BLOCKED：原因、受影響與依賴的步驟、需要什麼權限／資料／環境／說明才能繼續。沒有就寫「無」。>

## 截圖證據

<步驟或 AC 編號、一句說明、GitHub 附件網址的 Markdown 圖片；與結果表互相引用。沒有需要的截圖就寫「無」。>

## 清理狀態

<清理動作與結果、建立的資料 ID／網址、剩下的資料或允許延後的項目；沒建立資料就寫「未建立資料」。>

## 已知限制／本次未驗收範圍

<留言排除的項目、附帶觀察（不影響結果）、留言與 feature map 不一致之處。>

## 後續事項

<PASS：無需工程處理。
FAIL：需要修正並重驗的內容（對應失敗項與證據），不推測原因、不指定改法、不新增 AC。
BLOCKED：要排除的障礙與排除後怎麼重新請驗收。>
```
