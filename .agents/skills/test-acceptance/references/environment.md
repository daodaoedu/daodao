## 瀏覽器

依本輪可呼叫工具與網站授權選擇能完成原步驟的路徑；內建瀏覽器、已授權 Chrome／Edge 控制或 Playwright 等自動化工具均可，不綁定客戶端或品牌。選擇不增加控制無關 app、讀其他分頁／profile、變更網站權限或代登入他人帳號的授權；缺少一種工具先找等價能力，不直接要求使用者重開 session。

同一工具可測多個角色，不同工具也可分工，但各自檢查：

- **身分**：在實際操作頁面確認指定 Google 測試帳號與角色。各瀏覽器、profile／context 的登入互不相通；切換後重查，不匯出或複製 cookie、token，不用工程 dev-login。
- **畫面能力**：真實頁面可見、能完成原步驟；只讀 DOM 或 API 回應不能代替需要看畫面的判定。
- **原規格條件**：只設定交接／AC 要求的 viewport，讀回實際寬高並還原；需要的原生對話框、取消與確認均可操作。能力不足只阻擋依賴它的步驟，不擴測其他尺寸。
- **證據與發布**：依下節確認截圖、附件與發布身分，不因產品登入正確就推論 GitHub 身分正確。

手機尺寸與截圖能力須實測，不能由工具名稱推定：使用工具公開支援的 viewport／resize 功能，讀回 layout viewport 的 CSS px 寬高，與原步驟指定尺寸一致才測；視窗外框、截圖像素與 deviceScaleFactor 不能代替 CSS viewport。無法調整時查已授權的等價工具，切換後重新核對同一 Google 帳號與環境，測完還原原尺寸。若其他工作階段占用瀏覽器，不關閉、殺程序、接管分頁或複製認證；只使用工具支援的獨立 session／context，沒有安全獨立路徑就記受影響步驟受阻。

直接複製貼圖不可用時，查工具的截圖與檔案／附件上傳能力；必要暫存與上傳後回讀依「截圖與留言」。無法保全或上傳仍不是產品 FAIL；可繼續已確認資格及帳號下的獨立非消耗觀察，不能據此移 Need Fix。

工具發生錯誤時先讀該工具的診斷文件並核對網址。替代路徑須重新確認上述能力與網站授權；仍失敗才記錄嘗試、具體缺口與受影響項。不得改環境、語系、帳號或 AC 來湊通過。

toast 短暫出現時即時擷取；必要時用頁面 `[data-sonner-toast]` 文字輔助定位，但不能以文字代替必要版面／畫面證據。

## 截圖與留言

- 使用本次真實頁面擷取的截圖，標註原步驟／AC；先排除憑證、匿名回答與個人對應、無關個資及其他分頁內容，遮蔽須註明且不遮住判定依據。
- 直接貼圖或支援的附件上傳皆可。逐條確認上傳、留言與移卡路徑的 GitHub 身分為 `peggy1213-create`；不能把其他路徑的認證結果拿來放行，也不向未核對權限的外部圖床傳圖。
- 若工具需要檔案，可在本輪 owned 暫存目錄保存必要截圖、附件清單及 body-file；不得進 repo／Git、共享下載資料夾或永久公開的本機檔案服務。暫存不是已發布報告。
- 在一次性操作前，用本輪必要的非消耗畫面確認截圖可保全且附件路徑可交付；不為能力檢查另外發測試留言。未實際驗證的能力記未驗證，不能只看工具 schema 就宣稱可上傳。路徑受阻時繼續獨立非消耗觀察，停止無法保全／交付證據的消耗步驟。
- 依原流程只發一則報告，發布前核對所有必要圖已對應原步驟，發布後回讀作者、內容、附件與圖片顯示。必要圖缺失時不發缺圖報告，不移卡或關 issue；不能用工程報告替代本次證據。
- 圖片與報告回讀成功後、移卡／關卡前，清理本輪 owned 暫存檔並確認結果；失敗則停在交付未完成，不改產品判定。上傳／發布失敗時保留必要證據，記錄位置與待交付／待清理狀態，不在尚未交付時刪掉唯一證據；交接完成或使用者決定放棄後再清理，不把個資／憑證寫入報告。沒有檔案能力時在會話保留結果，不把缺少暫存視為已交付。

## App

**2026-10-29 起 App 暫不驗收**（使用者決定）：目前沒有可安裝的測試版（#333、#335、#358、#359 都曾因此受阻），請驗收留言裡的 App 步驟一律列為「本次未驗收範圍」，不判 BLOCKED，也不影響整體結果。判定方式見 SKILL.md §4。

- 不改用網頁版代替 App 步驟：網頁版不是同一個介面，網頁步驟只照留言裡本來就寫的網頁步驟測。
- 之後恢復驗收 App 時，留言必須給安裝方式（TestFlight 連結、內部分發連結或 Expo 入口），沒給或裝不起來就判 BLOCKED。
